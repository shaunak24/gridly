# v3.2 — Polish, account fixes, and invite deep links

**Status:** Complete.

## Scope

### Player-facing

- **Branded launch loading** — welcome and auth hydration show GridLogo and wordmark instead of a bare spinner
- **Sign-in navigation** — home appears once after sign-in with no visible double-load flicker
- **Per-user daily completion** — daily played/locked state follows the signed-in account; guest state stays device-local; switching accounts shows the correct daily state for each user
- **Invite links open the app** — tapping a shared Word Hunt HTTPS invite link on Android opens Gridly and starts the custom puzzle (not only a browser landing page)

### Engineering

- Android `intent://` fallback on the invite landing page; explicit `android.intentFilters` for `gridly://` game paths
- Single post-auth navigation path; dedupe `mergeLocalToCloud` on sign-in
- Account-scoped daily completion in local storage and merge policy (guest vs signed-in user)
- Shared `LaunchLoading` component for welcome, auth callback, and other boot screens

## Acceptance criteria

### Launch loading

- [x] While auth and welcome state hydrate, the user sees GridLogo, wordmark, and a subtle loading indicator on the themed background
- [x] No bare centered spinner on the welcome screen boot path

### Sign-in navigation

- [x] Email sign-in from `/auth/sign-in` navigates to home once with no back-flash or second home mount
- [x] Google sign-in from welcome, sign-in, and profile menu navigates to home once
- [x] OAuth callback (`/auth/callback`) navigates to home once

### Per-user daily completion

- [x] Guest completes Word Hunt or Grid Snap daily → daily button locked for guest on that device
- [x] Guest signs into account A that has not played today → daily is available for account A
- [x] Account A completes daily, signs out, account B signs in → account B sees its own daily state (not A's)
- [x] Signed-in daily completion syncs across devices for the same account
- [x] Sign-out restores guest daily completion state on the device (does not leak the signed-in account's lock to guest)

### Invite deep links (Android APK)

- [x] Tap shared HTTPS invite link in WhatsApp or Messages on Android → Gridly opens and custom puzzle starts with the correct word
- [x] If the browser landing page appears, **Open in Gridly** opens the app and starts the puzzle
- [x] Landing page auto-redirect uses Android intent URL when the user agent is Android
- [x] Invalid or expired invite still shows a friendly error in-app
- [x] Legacy `gridly://…?code=g1:…` links still work

## Out of scope

- Custom branded domain and verified App Links / Universal Links — see [backlog.md](./backlog.md)
- Game timers and mode-segregated stats — [v3.3.md](./v3.3.md)
- Grid Snap puzzle sharing

## Notes

v3.1 shipped HTTPS invite links and a browser landing page, but on Android the `gridly://` redirect from Chrome does not reliably open the installed APK. v3.2 closes that gap with Android intent URLs and explicit intent filters without requiring a custom domain.
