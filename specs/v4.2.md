# v4.2 — Word Hunt invite links actually open the puzzle

**Status:** Complete.

## Scope

### Player-facing

- **Shared invite links work** — tapping a Word Hunt share link opens Gridly and starts the puzzle with the correct word, instead of opening the app and reporting "This custom puzzle link is not valid."
- **Branded landing page** — the browser interstitial uses the Gridly mark, wordmark, and dark palette rather than unstyled defaults
- **Rich link previews** — invite links preview with a Gridly title and description in WhatsApp, Messages, and other chat apps instead of a bare URL
- **Helpful "not installed" state** — when the app does not open, the page explains why and offers the link to copy, rather than a dead end or an endless redirect loop
- **In-app browser guidance** — links opened inside Instagram/Facebook/WeChat WebViews explain how to reopen in a real browser
- **Create-puzzle modals show their text** — "Link copied" and "Share failed" rendered as title-only with an empty body
- **Offline is not "invalid"** — opening a valid link with no connection says to check the connection instead of claiming the link expired
- **Themed invite errors** — the play screen uses the app's modal instead of the OS alert, matching every other screen

### Engineering

- `_shared/landingPage.ts` — landing page extracted from the edge function, pure and unit-tested; all URLs travel as `data-*` attributes, never inside `<script>`
- `_shared/inviteLink.ts` — one canonical HTTPS invite URL builder shared by `create-invite` and `resolve-invite`
- `?fallback=1` loop guard on the Android `browser_fallback_url`
- `resolve-invite` answers `HEAD` and sends `Cache-Control: no-store`
- Optional `INVITE_OG_IMAGE_URL`, `INVITE_STORE_URL_IOS`, `INVITE_STORE_URL_ANDROID` function secrets
- `FetchInviteError.reason` (`network` | `not-found` | `unsupported`)
- Deleted the duplicated `src/platform/invites/buildAndroidIntentUrl.ts`; its test now covers `supabase/functions/_shared/deepLink.ts` directly
- `allowImportingTsExtensions` in `tsconfig.json`; Deno entrypoints excluded from the app typecheck

## Root cause

`renderLandingPage` ran the deep link through `escapeHtml()` and then interpolated the result into a `<script>` block. **HTML entities are not decoded inside `<script>`**, so the JavaScript string literally contained:

```
gridly://games/word-hunt/play?mode=custom&amp;invite=C4F1VhCHJGdQ
```

Parsed by the app that is `mode=custom` plus a param named `amp;invite` — the `invite` param was gone. `resolveMode` still returned `'custom'`, no invite and no legacy `code` were found, and the player got "This custom puzzle link is not valid." The `<a href>` fallback button was unaffected, because browsers *do* decode entities in attribute values — which is why the manual **Open in Gridly** button was the only path that ever worked.

Two further defects sat behind it:

- The Android `browser_fallback_url` was derived from `request.url`, which inside the Supabase edge runtime is `http://<ref>.supabase.co/resolve-invite/<id>` — wrong scheme, no `/functions/v1`. Anyone without the app landed on a dead URL.
- Fixing that alone would have created a redirect loop: Chrome falls back to the page, the page redirects to the intent, the intent fails, Chrome falls back again. Hence the `?fallback=1` guard, which suppresses the auto-redirect and renders the "not installed" state directly.

The fix removes the bug class rather than the bug: no dynamic value is interpolated into a `<script>` block at all. The page reads every URL from a `data-*` attribute with `getAttribute()`.

## Acceptance criteria

### Open invite (Android APK)

- [x] Tap a shared HTTPS invite in WhatsApp with Gridly installed → Gridly opens and the custom puzzle starts **with the correct word**
- [x] **Open in Gridly** button does the same
- [x] Link previews in chat show the Gridly title and description, not a raw URL
- [x] Without Gridly installed → branded "Don't have Gridly yet?" page, no redirect loop
- [x] Link opened in an Instagram/Facebook WebView → "Open this in your browser" guidance with a copyable link
- [x] Invalid or expired invite → branded "Puzzle not found" page
- [x] Legacy `gridly://games/word-hunt/play?mode=custom&code=g1:…` still opens the puzzle

### In-app

- [x] Invalid invite → themed modal (not the OS alert), returns to the Word Hunt hub
- [x] Valid invite with no connection → "Couldn't load this puzzle. Check your connection and try again."
- [x] **Copy link** and **Share failed** modals on the create-puzzle screen render their body text
- [x] Custom games still count toward Custom mode stats only

### Regression coverage

- [x] Unit test asserts no `&amp;` and no URL of any kind appears inside a `<script>` block
- [x] Unit test parses `data-deeplink` and asserts `invite` survives
- [x] Unit test asserts `S.browser_fallback_url` is the canonical `https://…/functions/v1/resolve-invite/<id>?fallback=1`

## Notes

**iOS is untested end to end.** There is no iOS dev build or TestFlight release today (`eas.json` has Android profiles only), so the browser → app hop was verified by reasoning and unit tests, not on a device. The `gridly://` route itself can be checked in the simulator with `npx uri-scheme open "gridly://games/word-hunt/play?mode=custom&invite=<id>" --ios`. Verify the full flow when an iOS build exists.

The optional OG image needs a one-time upload (see [supabase/README.md](../supabase/README.md)). Without it, previews still show the title and description — just no thumbnail.
